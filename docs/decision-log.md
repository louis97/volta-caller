# Volta decision log

This log records the product choices that shape Volta's first commercial
workflow.

| Decision                    | Alternatives considered                                                                         | Chosen approach and rationale                                                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Carrier selection authority | Let Volta automatically choose the lowest compliant quote; ask a coordinator to choose by phone | The dashboard customer selects a reviewed quote. Commercial preference can include price, trust, capacity, and service quality—context an agent should not infer.                                             |
| Booking authority           | Book during the initial carrier negotiation; require a second customer action before every step | Volta only confirms after an explicit dashboard selection. This keeps discovery fast while making commitment authorization unambiguous.                                                                       |
| Mandate enforcement         | Prompt-only rules; allow agents to make verbal exceptions                                       | The backend validates price, timing, cargo, state, and selected terms. Prompts guide conversation; software enforces authority.                                                                               |
| Carrier outreach            | Sequential coordinator calls; fully autonomous lowest-price auction                             | Volta collects and structures carrier offers, while the customer retains final choice. The product improves speed without sacrificing governance.                                                             |
| Changed confirmation terms  | Renegotiate automatically; silently choose another offer                                        | Fail the confirmation and escalate. A changed offer requires a fresh commercial decision and must not become an accidental booking.                                                                           |
| Quote data from calls       | Manual coordinator transcription; store raw transcripts only                                    | Persist structured quote records and extract final price, currency, agreement time, and summary from completed-call transcripts. This improves dashboard visibility while retaining the transcript for audit. |
| Exception response          | Leave incidents in chat/phone notes; automate replacement carriers                              | Capture verified facts, assess delivery feasibility against the mandate, notify the dashboard when risk exceeds the deadline, and escalate to a human. Replacement sourcing remains out of scope.             |
| Notification delivery       | Ephemeral toasts only; email/SMS as the first channel                                           | Persist shipment events first, then refresh the dashboard in real time. Events survive reloads and create an auditable record.                                                                                |
| Inbound operations channel  | Build inbound phone handling now; require a separate portal                                     | Keep the outbound carrier workflow focused. WhatsApp is the planned inbound channel for mandate intake and incidents, using the same backend records and notifications.                                       |
| Integration strategy        | Full TMS/ERP integration before validation; no integration model                                | Start with mocked integrations and a pilot lane. Prove operational value, then connect the buyer's TMS/ERP through defined backend interfaces.                                                                |
| Human handover on a live call | Park the carrier silently until someone notices; drop the call and have a human call back  | When Volta decides it needs a person, the call is offered to the console with a countdown (`awaiting_human`/`postponed`, `TAKEOVER_WINDOW_SECONDS`, default 5 min). If nobody accepts before it lapses, Volta closes in its own voice ("te devuelvo la llamada") instead of the line silently dying — a carrier left holding for an unwatched dashboard is worse than a clean close. `POST /api/calls/:callSid/accept` 409s on a stale click so it fails loudly rather than appearing to work. |
| Audio routing during handover | Bridge the carrier directly to the supervisor's phone line; let the agent stay on the line muted | A routing hub decides who is audible without ever touching the carrier's Twilio leg: carrier audio always feeds the agent (transcript never stops), the agent is heard only while it holds the floor, and the human is heard only once they accept. Being connected is not the same as holding the call — a supervisor merely listening in must not be audible, and the carrier's buffer is cleared on handoff so the agent's half-finished sentence doesn't play over the person who just joined. |
| Escalation lookup keying     | Trust a single session index (callSid) for supervision updates                                  | Sessions opened by a round key on `callSid`; ones bound by the media stream key on the stream sid. Supervision lookups now try both — a silent miss meant the countdown still ran and expired with nothing ever appearing on the floor, so a genuine miss now logs loudly instead of failing quietly. |
| Interruption sensitivity tuning | Fix per boot via environment variables; auto-detect the room acoustically | Turn-taking sensitivity is a per-session dial, not boot configuration — a Render redeploy is too slow to react mid-rehearsal. Two presets (speakerphone: threshold 0.9/900ms/far-field; handset: 0.6/500ms/near-field) are chosen on the testing panel right before a call launches, held only in memory (deliberately not persisted — it's a dial for the room, not durable config). |
| Deal approval mechanism      | Keep the standalone ApprovalRequest/ClosingAuthorization pipeline (dashboard "Approvals" view, `/api/approvals/*`) | Retired it — nothing created an ApprovalRequest anymore since `review_deal` replaced `request_quote_approval`, so it was dead code with no real consumer. Approving a carrier selection from VoltaChat or WhatsApp now goes through the already-proven `reviewedDeals`/`ClientSelection` model and calls the same `confirmationCoordinator.start()` path as the `/select-quote` endpoint — one approval path instead of two. |
| Live confirmation call routing | Hardcode the WebSocket handler to "negotiation" mode                                            | The handler now detects call mode via `getCallContext()`, and `finalizeConfirmation` actually finalizes (creates the Commitment via `createCommitmentFinalizer` and sends the WhatsApp recap) instead of being a no-op — the confirmation call and the negotiation call share the same live-audio pipeline but must diverge in what happens when the human agrees. |
| Quote capture on escalation   | Require the model to call `register_quote` separately from `trigger_escalation`                | If the model announces "I registered it" but only calls `trigger_escalation` (storing price solely in `escalations[].attemptedPriceMxn`), the dashboard silently showed "Awaiting quote" for a call that already had a price. Now escalation auto-registers a Quote first if none exists for that call — trust the model's stated intent over a strict two-call contract it doesn't reliably follow. |
| Confirmed address replacement | Freeze the first address given to each endpoint (pickup/destination) as final                   | The mandate builder now tracks which endpoint a street address was confirmed against and lets a later message explicitly replace it, instead of rejecting any mandate that no longer echoes an earlier-mentioned address verbatim. A shipper correcting an address mid-conversation is a normal case, not a validation failure — and the agent should not re-ask for an endpoint the user already confirmed. |
| Structured quote extraction   | Have the negotiating agent report the final agreed price itself; leave price recovery to manual transcript review | A separate, display-only pipeline runs a completed call's transcript through server-side structured output (`OPENAI_API_KEY` / `VOLTA_QUOTE_EXTRACTION_MODEL`) to recover final price, currency, and agreement time, stored per call as `pending`/`completed`/`unavailable`/`failed`. It never alters quotes, mandates, selections, or bookings — an unclear transcript is stored as `unavailable`, not guessed — keeping negotiation and audit-grade price recovery as independent, non-authoritative paths. |
| Call-to-mandate linkage       | Resolve which mandate a call belongs to from in-memory session state only                       | Each telephony call now persists its mandate/organization context durably (`telephony_call_contexts` table) instead of relying solely on the orchestrator's live session map. Render's process can restart or scale between call legs; the mandate link has to survive that, not just the call's lifetime in memory. |
| Console information architecture | Keep a single flat list of calls/quotes across all mandates                                  | The dashboard console is now organized per mandate, grouping calls, quotes, and pipeline state under the mandate they belong to instead of one undifferentiated stream — matching how a coordinator actually works (one shipment/mandate at a time) as call volume grows. |
